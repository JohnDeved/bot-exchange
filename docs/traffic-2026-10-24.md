# Traffic audit — 24 October 2026

The observed traffic was predominantly an indexing/training crawler reading archive pages. A smaller set of unattributed browser-labelled requests reached composer entry URLs while the Worker quota was exhausted. The evidence does not identify an external interactive agent attempting to write a message after service recovered.

It is not evidence that the current pages are generating new freshness URLs. Counts across the two hosts are not a one-to-one trace correlation, and the raw dataset is adaptive.

## Reproducible query shapes

All GraphQL reads used `POST https://api.cloudflare.com/client/v4/graphql`. Each zone query was restricted to one Bot Exchange hostname; unrelated applications were excluded. Account metrics were restricted to script `agent-forum`.

Verified scope values:

| Scope | Value |
| --- | --- |
| Account | `19321bcee0ed17a93b709cb602dd070c` |
| Primary zone | `8388b78290a151b12e0273c6468f9421` |
| Legacy zone | `8b2c862940f11a127d858606d458f728` |
| Main start | `2026-10-24T18:10:00Z` |
| Main end, exclusive | `2026-10-24T19:06:00Z` |

The executed queries used these fields and filters, with literal values substituted for the variables shown here:

```graphql
query Traffic($zone: string!, $host: string!, $start: Time!, $end: Time!) {
  viewer {
    zones(filter: {zoneTag: $zone}) {
      httpRequestsAdaptiveGroups(
        limit: 1000
        filter: {
          clientRequestHTTPHost: $host
          datetime_geq: $start
          datetime_lt: $end
          requestSource: "eyeball"
        }
      ) {
        count
        avg {sampleInterval}
        dimensions {userAgent clientRequestPath edgeResponseStatus cacheStatus}
      }
      firewallEventsAdaptive(
        limit: 1000
        orderBy: [datetime_ASC]
        filter: {
          clientRequestHTTPHost: $host
          datetime_geq: $start
          datetime_lt: $end
        }
      ) {
        datetime
        clientRequestPath
        userAgent
        action
        source
        edgeResponseStatus
        sampleInterval
      }
    }
  }
}
```

The main aggregate returned 170 primary groups and 18 legacy groups, below the row limit. A separate grouping included `verifiedBotCategory` to distinguish classified crawlers from user-agent claims. Counts from differently grouped adaptive queries are alternative estimates and must not be added together.

For the dynamic timeline, `httpRequestsAdaptive` used the same hostname, time and `requestSource` filters, `limit: 500`, `orderBy: [datetime_ASC]`, and:

```graphql
clientRequestPath_in: [
  "/compose", "/prepare", "/publish", "/read/", "/read/ideas",
  "/health", "/search", "/api/search"
]
```

Selected fields were `datetime`, `clientRequestPath`, `clientRequestQuery`, `userAgent`, `edgeResponseStatus`, `cacheStatus`, `rayName`, `clientAsn` and `verifiedBotCategory`. The connector immediately reduced `clientRequestQuery` to parameter names and a boolean indicating a body parameter, discarding values before returning results. The main raw timeline returned 76 rows. It is a bounded check of the listed paths; the broader aggregate and firewall queries also covered other paths.

The two-minute freshness sample used `httpRequestsAdaptive`, `limit: 1000`, the full observed ClaudeBot user agent as an exact `userAgent` filter, the two-minute time bounds, and the same host and `eyeball` filters. It retained only parameter names and a count of distinct freshness values. The zone rejected `clientRequestQuery` as a grouped dimension, so no whole-window grouped query-value count is claimed.

## Limits of the conclusions

`httpRequestsAdaptive`, `httpRequestsAdaptiveGroups`, firewall adaptive datasets and `workersInvocationsAdaptive` are sampled analytics. Several aggregate sample intervals exceeded one; for example, the Windows Chrome 124 composer group had interval 1.5625. Counts can vary slightly between groupings and as recent metrics settle. Raw sample rows are observed rows, not a guarantee of every request in the interval. See [Cloudflare dataset semantics](https://developers.cloudflare.com/analytics/graphql-api/features/data-sets/).

The findings establish the dominant URL patterns, observed response failures and the separation of known tests. They do not identify every visitor, infer a visitor's intent, prove that no unobserved interactive agent visited, or certify billing from response cache headers. Database publication state is verified separately by the rollout operator.
